# בונה הכלים (Tool Forge)

> אתה אומר למערכת מה אתה רוצה לנהל, והיא בונה לך אפליקציית AI קטנה ומותאמת, שנראית כמו לוח שליטה.

אפליקציית ווב שבה מתארים בשפה חופשית מה רוצים לנהל או לבצע, ומקבלים **לוח שליטה אישי** — שדות
קלט, סליידרים, כפתורי פעולה ורשימה שמצטברת. לא צ׳אט: מכשיר.

למשל, מוזיקאי מתאר "אני מקבל הערות מלקוחות על מיקסים", ומקבל לוח עם שדה להדבקת ההערות, סליידר
"רמת פירוט טכנית", כפתור "פרק לרשימת תיקונים" שמייצר רשימת תיקונים ממוינת לפי זמן בטראק, וכפתור
"נסח תשובה ללקוח".

## איך זה בנוי

הכול סובב סביב טיפוס אחד — `ToolSpec` (ראו `src/types.ts`). זהו מסמך JSON שמתאר לוח שליטה אחד:
קלטים, בקרות, פעולות (כל פעולה היא תבנית פרומפט) ואוספים (הזיכרון של הכלי). האפליקציה היא שתי
פונקציות סביב הטיפוס הזה:

| שלב | קובץ | מה קורה |
| --- | --- | --- |
| תיאור ← מפרט | `src/engine/claude.ts` · `src/engine/localBuilder.ts` | Claude בונה מפרט ב-structured outputs, או שמנוע התבניות המקומי בוחר תבנית לפי מילות מפתח |
| מפרט ← לוח | `src/pages/Console.tsx` | המפרט מרונדר לרכיבי UI; כל כפתור מריץ את הפרומפט שלו |
| הרצת פעולה | `src/engine/claude.ts` · `src/engine/localActions.ts` | הפעולה רצה מול Claude ומחזירה `{text, items}`, או מורצת מקומית במצב הדגמה |

`src/engine/specSchema.ts` מחזיק את סכימות ה-JSON שנשלחות ל-API ואת `normalizeSpec` — כל מפרט
שמגיע ממקור חיצוני (המודל, קובץ מיובא, localStorage ישן) עובר דרכה לפני שמריצים אותו.

## שני מצבי הפעלה

**מצב הדגמה (ברירת מחדל, בלי מפתח).** הפעולות מורצות מקומית: פירוק הקלט לפי סימני פיסוק, חילוץ
חותמות זמן וסכומים, ובניית טקסט תגובה שלדי. זה לא תחליף למודל — המטרה היא שהלוח ירגיש חי לפני
שמחברים מפתח, והפלט מסומן במפורש כהדגמה.

**מצב Claude.** מזינים מפתח API בהגדרות, וכל פעולה רצה מול `claude-opus-5` עם structured outputs.

> ⚠️ במסלול הזה המפתח נשמר ב-localStorage ונשלח ישירות מהדפדפן ל-Anthropic
> (`dangerouslyAllowBrowser`). זה מתאים לשימוש אישי במחשב שלכם בלבד. למשתמש שני — המסלול הבא.

### מסלול שלישי: שרת שמחזיק את המפתח

כשמגדירים כתובת שרת בהגדרות, **הדפדפן לא מחזיק מפתח בכלל**. הוא שולח `kind` + קלט, והשרת בונה
את הפרומפט ומדבר עם Anthropic:

```
דפדפן  →  { kind: 'buildSpec', args: [brief] }  →  api/claude.ts  →  Anthropic
                                                    ANTHROPIC_API_KEY
```

`api/claude.ts` הוא Web Fetch handler רגיל — עובד כפונקציית Vercel (קובץ ב-`api/` נעשה endpoint
אוטומטית), וגם ב-Cloudflare Workers או Deno Deploy. שתי ההגנות שהופכות אותו לשרת ולא לצינור פתוח:

1. **הלקוח לא שולח פרומפט.** הוא שולח סוג בקשה וקלט, והשרת בונה את הבקשה מ-`src/engine/requests.ts`
   — בדיוק אותו קוד שהלקוח היה מריץ. אי אפשר לבקש דרך הכתובת הזו משהו שהאפליקציה לא מייצרת בעצמה.
2. **`TOOLFORGE_ACCESS_TOKEN`** — אם הוגדר, כל בקשה חייבת לשאת אותו בכותרת `x-toolforge-token`.

משתני סביבה: `ANTHROPIC_API_KEY` (חובה), `TOOLFORGE_ACCESS_TOKEN` (מומלץ),
`TOOLFORGE_ALLOWED_ORIGIN` (ברירת מחדל `*`).

## הרצה

```bash
cd tool-forge
npm install
npm run dev      # פיתוח
npm test         # בדיקות
npm run build    # בנייה ל-dist/
npm run preview  # תצוגה מקומית של הבנייה
```

## בדיקות

`npm test` מריץ 69 בדיקות (Vitest) על הלוגיקה שהאפליקציה נשענת עליה. הן לא בודקות ניסוח של
פלט — הן בודקות את הכללים שאסור שיישברו:

| קובץ | מה נשמר שם |
| --- | --- |
| `src/tests/spec.test.ts` | אכיפת קטלוג היכולות: יכולת לא מוכרת נדחית ולא "מתוקנת" לקרובה אליה, יכולת שמשנה את העולם לא יכולה להיות כפתור, סוג הפלט נקבע על ידי היכולת, הרשאות נגזרות נכון, ומפרט זבל לא מפיל את האפליקציה |
| `src/tests/actions.test.ts` | פענוח תאריכים בעברית, הצבת ערכים בפרומפט, חילוץ פריטים במצב הדגמה, תקינות מזהה האירוע מול הדרישות של Google, ותיאורי הגרסאות |
| `src/tests/corpus.ts` | מאגר המקרים: תאריך יחסי, שעה חסרה, שעה לא חוקית, כמה מועדים, עברית ואנגלית מעורבות, וניסוח בלי שום פעולה |
| `src/tests/contract.test.ts` | שני שרתים מקומיים שמחזירים את המבנים האמיתיים של Anthropic ושל Google Calendar, כולל מקרי הכשל |

הכלל שהמאגר קיים בשבילו: **כשחסר מידע, המערכת מסמנת מה חסר ומורידה ביטחון במקום לנחש.** כל
מקרה במאגר נבדק גם על כך שהמועד המוצע בעתיד ושהביטחון יורד מתחת לסף כשמשהו חסר.

### מה נבדק בלי מפתח ובלי חשבון

`contract.test.ts` הוא הדבר הקרוב ביותר לקריאה אמיתית שאפשר להריץ כאן:

- **הסכימות נבדקות מול מגבלות structured outputs** — אין `minLength`, `maximum`, `pattern` וכל
  מילות המפתח שה-API דוחה; לכל אובייקט יש `additionalProperties: false` וכל מאפייניו ב-`required`.
  זה בדיוק סוג הטעות שהייתה מחזירה 400 בקריאה הראשונה.
- **מסלול Anthropic** מול שרת שמחזיר את מעטפת ה-Messages API: תשובה תקינה, `stop_reason: refusal`,
  ו-401. נבדק שהגוף שנשלח הוא מה שנבנה, ושכל מקרה כשל מתורגם להודעה מובנת.
- **מסלול Google Calendar** מול שרת שמחזיר את התשובות של Google: יצירה מוצלחת, **409 על מזהה
  תפוס** (וזיהוי שלו ככפילות), חיפוש חפיפה שמסנן לפי קרבה בזמן, מחיקה, ו-401 שמנקה את האסימון.

מה שזה **לא** מוכיח: שהמפתח שלכם תקף ושהחשבון שלכם מורשה. את זה אפשר לדעת רק בהרצה ראשונה
אצלכם. כלל התווים של מזהה האירוע כן אומת: מסמך ה-discovery הציבורי של Google
(`googleapis.com/discovery/v1/apis/calendar/v3/rest`) מגדיר `Event.id` כ-base32hex — a–v ו-0–9,
באורך 5 עד 1024 — וזה בדיוק מה שהקוד מייצר. אותו מסמך גם אישר את הנתיבים, את ה-scope
(`calendar.events` נמצא ברשימת ה-scopes של `events.insert`) ואת פרמטרי החיפוש שאנחנו שולחים.

הבדיקות רצות גם ב-CI לפני כל פריסה (`.github/workflows/deploy-tool-forge.yml`).

הבנייה משתמשת ב-`base: './'` ובניתוב hash, כך שהיא עובדת מכל נתיב אחסון (GitHub Pages, Render).
פריסה אוטומטית ל-GitHub Pages מוגדרת ב-`.github/workflows/deploy-tool-forge.yml`.

## קטלוג היכולות — ה-AI מרכיב, לא מתכנת

פעולה בלוח היא לא פרומפט חופשי. כל פעולה חייבת להצהיר על **יכולת** מתוך קטלוג סגור
(`src/engine/capabilities.ts`), וה-prompt רק מכוון אותה בתוך הגבולות של אותה יכולת.

| יכולת | מה היא עושה | משנה את העולם | דורש אישור |
| --- | --- | --- | --- |
| `extract.items` | פירוק טקסט לפריטים באוסף | לא | לא |
| `compose.text` | ניסוח טיוטה להצגה | לא | לא |
| `summarize` | סיכום ותמונת מצב | לא | לא |
| `plan` | סדר עדיפויות, שיבוץ, צעד הבא | לא | לא |
| `classify` | סיווג ותיוג פריטים | לא | לא |
| `calendar.createEvent` | יצירת אירוע ביומן | **כן** | **כן** |

מה שנאכף בקוד, לא רק בהנחיה:

- **הסכימה ל-Claude מגבילה את `capability` ל-enum** של הקטלוג, ו-`normalizeSpec` דוחה
  פעולה שמבקשת יכולת שלא קיימת — היא לא מתורגמת ליכולת קרובה, היא פשוט לא נוצרת.
- **יכולת שמשנה את העולם לא יכולה להיות כפתור.** היא מופעלת מפריט ועוברת בתור האישורים,
  ולכן אין מסלול שבו לחיצה אחת מבצעת פעולה חיצונית.
- **סוג הפלט נקבע על ידי היכולת**, לא על ידי מה שהמודל הצהיר — אין פער בין מה שהממשק
  מבטיח לבין מה שהמנוע עושה.
- **מסך ההרשאות נגזר מהיכולות** ומוצג בכלי עצמו: אם משהו לא מופיע שם, אין דרך שהכלי יעשה אותו.

מפרטים שנשמרו לפני שהקטלוג נוצר ממשיכים לעבוד — יכולת חסרה מוסקת מסוג הפלט של הפעולה.

## גרסאות וביטול

המפרט ניתן לעריכה ידנית ולבנייה מחדש, ולכן כל שינוי בו שומר קודם את הגרסה הקודמת. תחת "מתחת
למכסה המנוע" בכל כלי יש רשימת גרסאות, ולכל אחת **תיאור קריא של מה השתנה** — לא diff של JSON:

```
גרסה 1 · 1.8.2026, 11:28
· שם הכלי: "מפרק משימות" ← "מפרק משימות — גרסה שלי"
· הוסר כפתור: אני תקוע
```

שינוי ביכולת של כפתור מקבל שורה משלו, כי הוא משנה את מה שהכלי *רשאי* לעשות. שחזור מחזיר את
המפרט הישן ושומר את הנוכחי כגרסה חדשה — כלומר גם את השחזור אפשר לבטל. נשמרות עד 20 גרסאות לכלי.

## הפעולה החיצונית: Google Calendar

זו הפעולה היחידה שהמערכת יודעת לבצע מחוץ לעצמה, והיא בנויה סביב הכלל שאין דרך עוקפת:
לחיצה על **הוסף ליומן** בפריט לא מוסיפה כלום ליומן — היא מכינה טיוטה ומכניסה אותה
ל**תור האישורים**.

```
פריט ברשימה → טיוטת אירוע (Claude או פענוח מקומי)
            → בדיקת כפילות
            → תצוגה מקדימה + מד ביטחון + מקור המידע
            → אישור מפורש של המשתמש
            → יצירת האירוע
            → שמירת מזהה → ביטול אפשרי
```

מה שמחזיק את זה:

- **מצב סימולציה דלוק כברירת מחדל.** אישור מריץ הרצה יבשה; רק כיבוי מפורש בהגדרות מאפשר
  יצירת אירוע אמיתי.
- **מניעת כפילות בשתי שכבות.** Google מאפשר לקבוע מזהה אירוע מראש, ולכן אותו פריט תמיד מייצר
  אותו מזהה וניסיון שני נדחה ב-409. אבל Google מציינת במפורש שהיא **לא מתחייבת** לזהות
  התנגשות מזהים בזמן היצירה, בגלל האופי המבוזר של המערכת — ולכן זו לא הגנה מוחלטת. השכבה
  השנייה היא בדיקת חפיפה לפי כותרת וזמן שרצה לפני שהכרטיס מגיע לאישור, כך שהמשתמש רואה אירוע
  קיים לפני שהוא מאשר.
- **המערכת לא מנחשת.** כשחסר תאריך או שעה, הביטחון יורד, הכרטיס מסמן מה חסר, והמועד ניתן
  לעריכה לפני אישור.
- **ביטול.** מזהה האירוע נשמר, וכפתור אחד מוחק אותו.
- **היסטוריה מלאה** בהגדרות: מה הוכן, מה אושר, מה נדחה, מה נכשל ולמה.
- **האסימון בזיכרון בלבד.** אסימון הגישה של Google לא נשמר ב-localStorage ופג עם רענון הדף.
  ההרשאה מצומצמת ל-`calendar.events` — יצירה וצפייה באירועים, לא יותר.

להפעלה צריך `OAuth Client ID` משלכם (Google Cloud → הפעלת Calendar API → OAuth client מסוג
Web application → הוספת הכתובת שממנה האפליקציה רצה ל-Authorized JavaScript origins). מדביקים
אותו בהגדרות. אין צורך ב-client secret, ואסור להשתמש בו בדפדפן.

## התקנה על אנדרואיד

האפליקציה היא PWA — מותקנת מהדפדפן, בלי חנות ובלי APK:

1. פותחים את כתובת ה-GitHub Pages בכרום בטלפון.
2. תפריט ⋮ ← **התקנת אפליקציה** (או "הוספה למסך הבית").
3. היא נפתחת במסך מלא, עם אייקון משלה, ועובדת גם בלי רשת.

ה-service worker (`public/sw.js`) שומר את קליפת האפליקציה במטמון: מסמכים נטענים
network-first כדי לקבל גרסה עדכנית כשיש רשת, ונכסים סטטיים cache-first כדי שהפתיחה תהיה
מיידית. הכלים והפריטים ממילא יושבים ב-localStorage, ולכן הכול זמין גם במצב טיסה.

> רוצים APK אמיתי לחנות? אפשר לעטוף את אותה בנייה ב-Capacitor. זה דורש התקנת Android SDK
> וחתימת המפתח שלכם — לא נעשה כאן.

## מה נשמר איפה

הכול בדפדפן, ב-localStorage: הכלים (`toolforge.tools.v1`), המצב של כל כלי — ערכי שדות, בקרות,
פריטים ויומן הרצות (`toolforge.states.v1`), וההגדרות (`toolforge.settings.v1`). בהגדרות אפשר
לייצא את הכלים לקובץ JSON ולייבא אותם במכשיר אחר.

## מגבלות ידועות

- לכלים אין גישה למקורות חיצוניים — לא ליומן, לא למייל ולא לאינטרנט. הם עובדים על מה שמדביקים
  לתוכם. פעולה כמו "בדוק ביומן" תחזיר הצעה לשיבוץ, לא תכתוב ליומן.
- מנוע התבניות המקומי מכסה שמונה תחומים (`src/engine/patterns.ts`). תיאור שלא נופל לאף אחד מהם
  יקבל לוח כללי — או לוח מותאם באמת, אם מחוברים ל-Claude.
- מסלול ה-Claude נכתב לפי המפרט המתועד של ה-API אך לא הורץ מול המפתח שלכם; הרצה ראשונה עשויה
  לדרוש התאמות קטנות.
