# בונה הכלים (Tool Forge)

> אתה אומר למערכת מה אתה רוצה לנהל, והיא בונה לך אפליקציית AI קטנה ומותאמת, שנראית כמו לוח שליטה.

אפליקציית ווב שבה מתארים בשפה חופשית מה רוצים לנהל או לבצע, ומקבלים **לוח שליטה אישי** — שדות
קלט, סליידרים, כפתורי פעולה ורשימה שמצטברת. לא צ׳אט: מכשיר.

למשל, מוזיקאי מתאר "אני מקבל הערות מלקוחות על מיקסים", ומקבל לוח עם שדה להדבקת ההערות, סליידר
"רמת פירוט טכנית", כפתור "פרק לרשימת תיקונים" שמייצר רשימת תיקונים ממוינת לפי זמן בטראק, וכפתור
"נסח תשובה ללקוח".

## איך זה בנוי

הכול סובב סביב טיפוס אחד — `ToolSpec` (ראו `src/types.ts`). זהו מסמך JSON שמתאר לוח שליטה אחד:
קלטים, בקרות, פעולות (כל פעולה היא תבנית פרומפט) ואוספים (הזיכרון של הכלי). האפליקציה היא שתי
פונקציות סביב הטיפוס הזה:

| שלב | קובץ | מה קורה |
| --- | --- | --- |
| תיאור ← מפרט | `src/engine/claude.ts` · `src/engine/localBuilder.ts` | Claude בונה מפרט ב-structured outputs, או שמנוע התבניות המקומי בוחר תבנית לפי מילות מפתח |
| מפרט ← לוח | `src/pages/Console.tsx` | המפרט מרונדר לרכיבי UI; כל כפתור מריץ את הפרומפט שלו |
| הרצת פעולה | `src/engine/claude.ts` · `src/engine/localActions.ts` | הפעולה רצה מול Claude ומחזירה `{text, items}`, או מורצת מקומית במצב הדגמה |

`src/engine/specSchema.ts` מחזיק את סכימות ה-JSON שנשלחות ל-API ואת `normalizeSpec` — כל מפרט
שמגיע ממקור חיצוני (המודל, קובץ מיובא, localStorage ישן) עובר דרכה לפני שמריצים אותו.

## שני מצבי הפעלה

**מצב הדגמה (ברירת מחדל, בלי מפתח).** הפעולות מורצות מקומית: פירוק הקלט לפי סימני פיסוק, חילוץ
חותמות זמן וסכומים, ובניית טקסט תגובה שלדי. זה לא תחליף למודל — המטרה היא שהלוח ירגיש חי לפני
שמחברים מפתח, והפלט מסומן במפורש כהדגמה.

**מצב Claude.** מזינים מפתח API בהגדרות, וכל פעולה רצה מול `claude-opus-5` עם structured outputs.

> ⚠️ המפתח נשמר ב-localStorage ונשלח ישירות מהדפדפן ל-Anthropic (`dangerouslyAllowBrowser`).
> זה מתאים לשימוש אישי במחשב שלכם בלבד. אל תפרסמו מופע עם מפתח מוטמע, ואל תשתמשו במפתח ארגוני —
> מוצר שמשרת משתמשים אחרים צריך שרת ביניים שמחזיק את המפתח.

## הרצה

```bash
cd tool-forge
npm install
npm run dev      # פיתוח
npm run build    # בנייה ל-dist/
npm run preview  # תצוגה מקומית של הבנייה
```

הבנייה משתמשת ב-`base: './'` ובניתוב hash, כך שהיא עובדת מכל נתיב אחסון (GitHub Pages, Render).
פריסה אוטומטית ל-GitHub Pages מוגדרת ב-`.github/workflows/deploy-tool-forge.yml`.

## התקנה על אנדרואיד

האפליקציה היא PWA — מותקנת מהדפדפן, בלי חנות ובלי APK:

1. פותחים את כתובת ה-GitHub Pages בכרום בטלפון.
2. תפריט ⋮ ← **התקנת אפליקציה** (או "הוספה למסך הבית").
3. היא נפתחת במסך מלא, עם אייקון משלה, ועובדת גם בלי רשת.

ה-service worker (`public/sw.js`) שומר את קליפת האפליקציה במטמון: מסמכים נטענים
network-first כדי לקבל גרסה עדכנית כשיש רשת, ונכסים סטטיים cache-first כדי שהפתיחה תהיה
מיידית. הכלים והפריטים ממילא יושבים ב-localStorage, ולכן הכול זמין גם במצב טיסה.

> רוצים APK אמיתי לחנות? אפשר לעטוף את אותה בנייה ב-Capacitor. זה דורש התקנת Android SDK
> וחתימת המפתח שלכם — לא נעשה כאן.

## מה נשמר איפה

הכול בדפדפן, ב-localStorage: הכלים (`toolforge.tools.v1`), המצב של כל כלי — ערכי שדות, בקרות,
פריטים ויומן הרצות (`toolforge.states.v1`), וההגדרות (`toolforge.settings.v1`). בהגדרות אפשר
לייצא את הכלים לקובץ JSON ולייבא אותם במכשיר אחר.

## מגבלות ידועות

- לכלים אין גישה למקורות חיצוניים — לא ליומן, לא למייל ולא לאינטרנט. הם עובדים על מה שמדביקים
  לתוכם. פעולה כמו "בדוק ביומן" תחזיר הצעה לשיבוץ, לא תכתוב ליומן.
- מנוע התבניות המקומי מכסה שמונה תחומים (`src/engine/patterns.ts`). תיאור שלא נופל לאף אחד מהם
  יקבל לוח כללי — או לוח מותאם באמת, אם מחוברים ל-Claude.
- מסלול ה-Claude נכתב לפי המפרט המתועד של ה-API אך לא הורץ מול המפתח שלכם; הרצה ראשונה עשויה
  לדרוש התאמות קטנות.
